The Solution

Web3Cash — real cash for real
on-chain actions.

A two-sided marketplace: Web3 projects pay per verified user action (installs, deposits, trades, follows), and users earn real USDC cashback withdrawable to any wallet. A lifetime referral engine (10% forever, 2 levels) creates zero-CAC viral distribution. A subscription tier adds recurring revenue on top.

Core Differentiator
Real USDC — not points
Every reward paid in USDC stablecoins. Competitors (Galxe, Layer3, Zealy) pay in project tokens, NFTs, or locked points. USDC is immediately liquid, withdrawable to any EVM wallet, and universally valued.
Viral Engine
10% lifetime referral
Refer a user, earn 10% of every reward they ever earn — forever. Level 2 earns 3%. Capped at 2 levels to preserve unit economics. In crypto Telegram groups, this mechanic spreads within hours.
B2B Positioning
Performance marketing vocabulary
Projects buy CPI, CPA, CPL, CPS, CPC — the same language Web2 growth teams already understand. Lowering the mental barrier to buying is a distribution advantage, not just a UX choice.
Trust Layer
Verified projects + escrow
Projects escrow USDC before any quest goes live. Users are guaranteed payment — no rug-pull possible. Project verification badge system ensures only KYC'd, legitimate projects can list quests.
Anti-Fraud
On-chain Sybil protection
Wallet age, transaction history depth, gas spend patterns, and social proof layer prevent bot farms. The verification engine is the core IP and primary moat — it's what makes projects trust the platform.
Revenue Layer
Subscription tier (Crodeye)
$5/$10/$25 per month tiers unlock larger rewards, exclusive quest access, priority verification, and higher referral rates. Converts the performance marketing fee model into predictable recurring ARR.
Platform Architecture

Full system overview — every layer
from frontend to blockchain.

Two primary clients (User Web App and Project Dashboard) communicate through a unified API Gateway. Seven microservices handle distinct domains. A multi-chain indexer watches on-chain state. An escrow smart contract holds project funds in trust. All data flows through PostgreSQL with Redis for caching and queue management.

User Flows

Every user journey mapped — from
wallet connect to USDC in pocket.

Four primary user journeys covering registration, quest completion, referral attribution, and cashback withdrawal. Each flow is designed to minimize friction while maximising the verification signal needed to prevent fraud. Wallet-connect is the primary auth — no username/password required.

User lands on Web3Cash, connects wallet via WalletConnect or MetaMask, signs a message to prove wallet ownership (no gas cost), and is scored for Sybil risk before being allowed to complete quests. High-risk wallets are flagged, not blocked — they go through a manual review queue.

Diagram 3 — Quest discovery and completion flow · 6 quest types
Every user gets a unique referral code. When a referred user completes any quest, the referrer earns 10% of the gross reward value — not 10% of the user's net payout. If that referred user also refers someone (level 2), the original referrer earns 3%. Payouts are capped at 2 levels to protect unit economics. Attribution is deterministic and stored on-chain via the escrow contract.

Project Flows — B2B Side

How Web3 projects create campaigns,
fund escrow, and track ROI.

The B2B side is the revenue engine. Projects register, get verified, deposit USDC into escrow, configure quest campaigns with specific action types and reward amounts, and monitor performance through a self-serve dashboard. Billing is per verified completion — no upfront commitment beyond the escrow deposit.

Project onboarding is intentionally manual for the first cohort — the sales team handles KYC and escrow setup to ensure only legitimate projects are listed. Starting from Month 4, a self-serve onboarding flow replaces the manual process for projects above a minimum escrow threshold of $2,000 USDC.

Technical Architecture

The hard engineering problems — verification,
fraud, smart contracts, multi-chain.

The verification engine is the core IP of Web3Cash. It must answer: did this specific wallet address perform this specific on-chain action, within the campaign window, with funds above the threshold, and did they actually use the product rather than simulate it? Different quest types require different verification methods — on-chain indexing for deposits, webhook events for installs, API polling for social actions.

Sybil detection runs in two phases: at registration (to set the base score) and at quest completion (to catch wallets that improved their score by farming other platforms). Data Architecture

Database schema — every entity
and relationship that matters.

The core data model has 10 primary entities. Users and Projects are the two top-level actors. Campaigns belong to Projects, Quests belong to Campaigns, and QuestCompletions are the transactional core. VerificationLogs provide the audit trail. Referrals and Payouts handle the financial flows. Subscriptions manage tier access.

referralsIndex on (referrer_id, level) — powers referral tree queries
Cache Strategy (Redis)
Quest feedCached 60s — high read, low write · invalidated on quest update
User sybil scoreCached 7 days · recalculated on schedule not per-request
Project campaign statsCached 30s · real-time feel without DB hammering
User balanceNOT cached — always read from DB to prevent stale balance on withdrawal
Rate limit countersRedis INCR with TTL — atomic, fast, no DB overhead
Business Model & Revenue

Three revenue streams. One flywheel.
Every user makes the platform more valuable.

For every verified quest completion: the project pays the gross amount, Web3Cash takes a 15% margin, the referral layer takes up to 13% (10% level 1 + 3% level 2), and the user receives the net reward. Across 100,000 monthly completions at $10 average reward, this generates $150,000/month in gross margin before referral payouts.

Risk Register

What can kill this product — and
exactly how to prevent it.

01
Critical
Sybil attack drains project campaign budgets in hours
Bot farms with thousands of fresh wallets complete all quests before real users can access them. Projects get refunded nothing — they see 500 completions but zero real users. One incident destroys platform credibility. Mitigation: all quests gate on minimum Sybil score 40 by default; no completion is paid without a 30-minute hold window; velocity limits (max 5 completions per wallet per hour) fire before the escrow releases. Contract has a payout pause function controlled by a multisig admin key.
02
Critical
Smart contract vulnerability — escrow funds stolen
Any bug in the escrow contract could result in loss of all project-deposited USDC. This is existential — one exploit ends the company. Mitigation: contract is minimal by design (under 200 lines); third-party audit before mainnet deployment (Certik, Spearbit, or Code4rena); bug bounty program from day one; circuit breaker — admin multisig can pause all payouts if anomalous drain detected; campaign TVL capped at $50k per campaign until audit completed.
03
Critical
Regulatory classification as unlicensed money transmitter
Paying real USDC to users globally could trigger FinCEN (US), FCA (UK), and RBI (India) money transmission requirements. Licenses cost $500k+ and take 18 months. Mitigation: structure all payouts as stablecoin rewards not fiat; incorporate in a crypto-friendly jurisdiction (Cayman Islands, BVI, or UAE) before launch; KYC gate at $500 creates a defensible compliance posture; obtain a legal opinion in Month 2 — not Month 6.
04
High
Referral economics collapse into a Ponzi-like structure at scale
If a user recruits 5 friends who each recruit 5 more, the referral payout tree can exceed margin on high-completion-volume users. Mitigation: hard cap at 2 levels — no exceptions; referral percentages (10% / 3%) are calculated on gross reward before Web3Cash margin, meaning the margin always covers the referral cost; if total referral payouts in a given month exceed 30% of gross margin, the system flags for review and temporarily reduces the L2 rate.
05
High
Verification false positives — real users blocked as bots
Over-aggressive Sybil scoring blocks legitimate new wallet users (especially in emerging markets where users have less on-chain history). Mitigation: social proof pathway — linking Twitter or Discord with minimum activity unlocks quests even for young wallets; manual review queue processes appeals within 24 hours; separate Sybil thresholds per quest tier — basic quests require score 20+, high-value deposit quests require 70+; monitor false positive rate weekly and adjust signal weights accordingly.
06
High
Indexer downtime causes verification failures during high-traffic campaigns
If Alchemy or Moralis has an outage during a major campaign launch, thousands of legitimate completions cannot be verified. Users don't get paid. Project claims the platform is broken. Mitigation: dual-indexer architecture — Alchemy primary, Moralis fallback with automatic switchover; verification jobs have a 4-hour retry window before failing permanently; status page showing indexer health in real time; Datadog alert fires to on-call if event lag exceeds 60 seconds.
07
Medium
Competitor (Layer3, Galxe) copies the USDC payout model
Galxe has 15M users and could add USDC payouts overnight. Layer3 is growing fast. Mitigation: the moat is not the USDC idea — it's the verified-payout proof (the verification engine), the referral network effects, and the project relationships. Focus on locking in 50+ projects with annual contracts by Month 6. Project switching cost is high once their analytics data, user history, and webhook integrations are built around Web3Cash.
